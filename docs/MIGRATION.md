# Migration notes

Deliberate behaviour and API changes on the `research-quality` branch, by work
package. The CHANGELOG is written in WP9 from these notes.

## WP0

- **Python 3.11 or newer** is required (`requires-python = ">=3.11"`).
- **`great_tables` is optional.** Install `coned_billing[report]` to use
  `rate_schedule_summary_table()`. Without it the function raises an
  `ImportError` that names the extra. The previous built-in stand-in object
  is gone; `rate_schedule_summary_dataframe()` is unchanged and needs no
  extra. The returned table no longer carries a `_source_df` attribute; call
  `rate_schedule_summary_dataframe()` for the data.
- **`coned_billing.supply_charge` no longer runs on import.** Importing it
  used to download a CSV, print averages and create a temporary file. The
  legacy behaviour now runs only via `python -m coned_billing.supply_charge`,
  and its signed URL expired in October 2025. Do not use it for research
  results; WP8 replaces it.
- **Package metadata** declares the existing restrictive `LICENSE.txt`
  (`LicenseRef-FREE-All-Rights-Reserved`) instead of MIT.
- Billing results are unchanged. `RateSchedule.bill` now gives the same
  output on pandas 2.2 and pandas 3; it used to fail on pandas 3.

## WP1

- **New:** `LoadProfile`, `read_load_csv`, `Gap`, `ConEdBillingError` and
  `LoadDataError` (a `ValueError` subclass) are exported from `coned_billing`.
  The input contract is documented in `docs/load_data.md`.
- **Energy no longer depends on `.freq`.** Before, energy came from the
  index's `.freq`, or else from backward timestamp differences, with the
  first interval assumed to last 1 h. Now it is always kW × the validated
  interval duration. Results change for any input that lacked `.freq`, such
  as data read from CSV: four 15-minute rows at 1 kW now give 1.00 kWh, where
  they used to give 1.75 kWh.
- **Irregular or gappy input is rejected** with `LoadDataError`. It used to
  be billed as stretched intervals. Pass `on_gap="allow"` to bill only the
  observed intervals. Irregular grids are not supported.
- **Months and TOU windows use New York time.** A UTC-indexed load used to be
  billed by UTC months and hours; it is now converted to New York time first.
- **`RateSchedule.bill`** gains keyword-only `interval=`, `label=` (default
  `"start"`, the old implicit convention) and `on_gap=`. With no `interval`,
  it is taken as the smallest timestamp spacing, and fewer than 2 rows then
  raise an error. Timezone-naive DataFrame indexes are rejected.
- **`n_customers`** must be a positive integer (booleans rejected).
- **`billing.bill()` and the `coned-bill` CLI** read the CSV through
  `read_load_csv`, so files that span a DST change now work. New options are
  `interval` and `label` (CLI: `--interval`, `--label`), defaulting to
  hourly, interval-start. Naive CSV timestamps are rejected; they used to be
  parsed as naive and billed in whatever time they happened to be in.
- **Negative kW values** are rejected on this import-only path. They used to
  be billed as negative consumption.

## WP2

- **Holidays are matched on the New York civil date.** Before, holiday
  dates were compared with naive dates, so a timezone-aware load never
  matched and holidays were billed as ordinary days. Bills for windows that
  exclude holidays change for any tz-aware input. The largest effect in the
  bundled tariffs is SC-9 Rate II, whose legacy YAML excludes holidays from
  its on-peak demand windows (see finding N1 in `docs/calendars.md`).
- **Holidays are generated by rule for any year.** Thanksgiving is now the
  fourth Thursday in November (it was the first), and years outside
  2020–2030 work. No observed-day shift is applied.
- **Holiday sets per window.** New `excluded_holidays` field on `TimeWindow`
  and in YAML: a set name (`none`, `coned_six`, `sc1_rate2_summer`,
  `sc1_rate2_nonsummer`), a list of holiday names, or a `HolidaySet`. The
  default stays the six-day set. Setting it together with
  `include_holidays: true` is an error. The private `_CONED_HOLIDAYS` is
  removed; use `HOLIDAY_SETS` or `get_holiday_set`.
- **`is_coned_holiday`** returns a plain `bool` for a scalar (it raised
  `AttributeError`) and a NumPy bool array for an index, and takes a
  `holiday_set` argument.
- **End of day.** `"24:00"` is rejected with an error naming the new
  `end_of_day` token; `end` may also be omitted. Times must be `HH:MM`.
- **Window validation.** `TimeWindow` now rejects overnight windows
  (`end <= start`), seconds in times, months outside 1–12, empty or
  duplicated months, and a non-boolean `weekdays_only`. `months` is stored
  as a tuple.
- **`TimeWindow.mask`** rejects timezone-naive input and converts other time
  zones to New York.

## WP3

- **New: dated, source-cited tariff versions.**
  - The new API is `coned_billing.tariff_schema` (exported as
    `TariffRegistry`, `TariffVersion`, `default_registry` and
    `load_tariff_version`), documented in `docs/tariff_schema.md`.
  - The bundled versions cover SC-1 Rate I and SC-2 Rate I from 2019-01-01,
    and SC-8 Rate I LT, SC-9 Rate I LT/HT and SC-9 Rate II LT from
    2020-02-01. All run up to the current 02/01/2026 leaves and are
    `transcribed`.
  - Each bundled tariff also has an `unverified`, scenario-only `legacy`
    version holding the old values unchanged.
  - The billing engine does not use the new versions until WP5.
- **`load_rate` rejects unknown keys.**
  - Unknown or misspelled keys in legacy tariff files now raise
    `ConEdBillingError` naming the key, for example `weekday_only`. Before,
    they were ignored silently, which turned a weekday window into an
    all-days window.
  - The only new key is `notes`.
- **`sc_1_res_rate_1.yml`:** the scratch notes under the stray top-level key
  `0:` now sit, unchanged, under `notes:`. No rate changed. The `legacy`
  version records them in `legacy_notes`.
- **Errors:** new `TariffSchemaError` (a `ValueError`) and
  `TariffSelectionError` (a `LookupError`), both subclasses of
  `ConEdBillingError`.
- **Packaging:** the wheel now carries `tariffs/v1/`. The cited source PDFs
  under `docs/sources/` stay in the repository only.
- **SC-9 Rate II holidays:** the transcribed versions exclude no holidays,
  following leaf 449 (owner decision, 2026-10-23). The legacy file keeps its
  six-holiday exclusion.
